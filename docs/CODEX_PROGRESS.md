## 2026-10-28 — 12개월 달력 인덱싱/표시 정확성 개선 (검토용 브랜치)

- 수정: `src/lib/award-evidence.ts` — `buildEvidenceIndex()` 추가. 출발지/목적지/일자/마일리지 프로그램/좌석등급별로 자료를 1회 색인하여 달력 날짜를 조회할 때 전체 배열을 반복 탐색하지 않음.
- 수정: `getDayEvidence()` — 기존 배열과 새 색인 입력을 모두 지원하며, `checkedDestinations`, `requestedDestinations`, `partial` 범위를 반환. 일부 목적지만 확인된 '좌석 표시'도 전체 조회 완료로 오인하지 않도록 분리. 다른 목적지의 같은 편명도 독립 항공편으로 계산.
- 수정: `src/components/verified-award-dashboard.tsx` — 색인은 useMemo로 만들고 월별/연간 7열 달력에서 공유. **연간 달력에도 마일리지 프로그램·좌석 등급 필터 적용**. '표시 없음 / 대기 / 일부 조회 / 미조회'를 구분.
- 수정: `src/lib/award-evidence.test.mjs` — 색인/비색인 결과 일치·부분 조회·중복 목적지·편명 충돌·최신 자료 우선 회귀 테스트 5종 추가.
- 로컬 검증: 이번에 작성한 로직과 동일한 색인 함수를 이전 소스 ZIP에 이식한 **분리 시험판**에서 `tsc --noEmit` 통과, Node 단위 테스트 **11/11 통과**. 전체 실제 저장소 `npm run build`, React/브라우저 QA는 아직 재실행하지 못함.
- 합성 성능 시험: 정규화한 가상 12,000개 자료에서 조회 2,000회 기준 배열 반복 검색 **277ms**, 색인 생성+검색 **16ms** (컨테이너 단일 실행의 참고 수치; 실제 사용자 화면/네트워크 응답 성능을 보장하지 않음).
- 공식 데이터 연결: **여전히 미구현/미검증**. 자료가 없는 날짜에는 가상 좌석 수를 표시하지 않음.
- 다음 단계: Codex 환경에서 `npm ci`, `npm run typecheck`, `npm test`, `npm run build`, Chrome/모바일 달력 회귀 QA. 이후 공식 데이터 제공 경로의 허용 범위와 조회 속도를 실측하고 어댑터 연결.
- 기존 main 및 배포 서비스는 변경하지 않음.
