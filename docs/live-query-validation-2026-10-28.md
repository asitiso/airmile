# 실제 대한항공 조회 실행 결과 — 2026-10-28

## 결론

공식 사이트에서 실제 Chrome 조회를 실행했다. **이번 환경에서는 좌석 자료 취득에 성공하지 못했다.** 공항 선택 코드의 오류는 수정했지만, 월간 결과를 기다리는 동안 대한항공 도메인의 요청에서 **HTTP 403 접근 거부**를 관찰했다. 이를 모든 클라우드/모든 이용자의 접속 불가로 일반화하지 않는다. 정확한 차단 리소스와 항공사 운영 정책은 이 시험으로 확정할 수 없다.

이 문서는 이전 CODEX_PROGRESS.md의 '공식 사이트 실행 미검증' 상태를 갱신하는 실제 실행 기록이다. 인터뷰 80개 요구사항은 바꾸지 않는다.

## 실제 수정한 코드

1. `scripts/ke-airport-ui.mjs`: 공항 코드를 화면 글자 대신 접근성 이름으로 찾는다. 임의 첫 항목 선택을 없애 모호한 결과는 실패시킨다.
2. `scripts/ke-airport-ui.test.mjs`: 합성 HTML 브라우저 회귀 테스트 2개. 원래 선택자로 2개 실패 → 수정한 선택자로 2개 통과. 합성 화면은 공식 좌석 데이터가 아니다.
3. `scripts/ke-access-guard.mjs`: 401/403/429를 받으면 기다리던 작업을 즉시 실패 처리한다. 이미 접근 거부된 상태에서는 다음 UI 작업을 시작하지 않는다. API 응답 본문은 읽지 않는다.
4. `scripts/ke-access-guard.test.mjs`: 대기 중단·후속 작업 억제·타 도메인 구분·상태코드·리스너 해제 5개. 이전 동작에서 4개 실패, 수정 후 5개 통과.
5. `scripts/collect-ke-public.mjs`: 위 기능을 연결하고 수집 성공·브라우저 종료 후에만 JSON을 저장한다. 실패하면 기존 증거 파일을 교체하지 않는다.

## 다음 개발 판단

허용된 접근 경로에서 실제 데이터가 반환되는 것을 먼저 입증해야 한다. 이 실행 환경에서 반복 호출하거나 더 많은 월/목적지로 확장하지 않는다. 사용자 PC에서의 허용된 공식 UI 조회 또는 권한을 확보한 공급자 연동은 별도 검증 대상이며, 이번 실패로 성공을 보장하지 않는다.
