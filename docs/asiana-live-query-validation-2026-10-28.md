# 아시아나 실제 공개 달력 조회 검증 — 2026-10-28

## 현재 결론

**이번 GitHub Actions 실행 환경에서는 아시아나 좌석 데이터를 확보하지 못했다.** 대한항공의 기존 403 경로는 재시도하지 않았다. 아시아나를 독립적으로 검사했고, 마지막 시험에서 아시아나 도메인의 HTTP 403을 관찰한 뒤 중단했다. 이 결과는 모든 클라우드나 사용자 PC의 접속 불가를 증명하지 않는다.

- 요청 범위: ICN → NRT, 2026년 11월 한 달.
- 인증: 로그인하지 않은 새 Chrome 프로필. 사용자 계정·비밀번호·기존 쿠키 사용 없음.
- 동작: 공식 공개 페이지에서 편도/공항/탑승월/조회 버튼을 일반 UI 조작으로 선택하려고 시도.
- 결과: **취득한 실제 좌석 자료 0건**, 수용한 AwardEvidence 0건. 조회 실패는 매진이 아니다.
- 실시간 인원별 발권 가능 여부, 세금, 마일리지 가격, 모든 항공편 수집 여부: 검증하지 못함.
- 캐시 2초 / 신규 첫 실제 결과 10초 목표: 데이터 취득 실패로 달성 여부를 검증하지 못함.

## 안전한 중단과 기록

- 대한항공의 제한 경로에 추가 요청하지 않았다.
- 아시아나의 403 이후 IP/프록시/사용자 에이전트 변경, 인증정보 복제, 보안 확인 자동 처리를 하지 않았다.
- 비공개 API를 직접 호출하거나 응답을 재전송하지 않았다. 실패한 공항 정보 URL은 브라우저가 요청한 경로명을 기록한 것이며 직접 호출한 것이 아니다.
- 라이브 시험 워크플로는 `workflow_dispatch`만 남겼고 기본값 false인 `access_reviewed` 확인을 요구한다. push·schedule 자동 실행은 없다.
- 로그에는 익명 검색의 공항 코드·입력 상태·제한 코드만 남긴다. 인증 쿠키·토큰·사용자 개인정보는 수집하지 않는다.
- `probe-results`의 JSON은 진단 결과일 뿐 `records` 입력 형식이 아니므로 앱의 실제 좌석으로 반입하지 않는다.

## 공식 문서와 실제 시험을 구분

아시아나 공식 조회 페이지는 공개 현황이 일 1회 갱신되며 향후 360일을 제공한다고 안내한다. 웹 검색 도구가 반환한 페이지에는 과거 기준시각이 있었으므로 그 내용을 오늘의 좌석 재고로 사용하지 않았다.

- 공식 페이지: https://flyasiana.com/I/KR/KO/MileageSeatSearch.do
- Chromium의 HTTP2 비활성화 옵션 정의: https://chromium.googlesource.com/chromium/src/+/HEAD/components/network_session_configurator/common/network_switch_list.h

페이지 설명을 읽는 데 성공한 것, 앱 빌드가 성공한 것, 실제 월별 좌석을 취득한 것은 각각 다른 검증이다.
